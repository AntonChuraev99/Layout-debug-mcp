## Шаг 1 — правки

Правки пользователя по UI записываются сюда по мере поступления.

### Итерация 1 — шапка и правая панель (2026-10-06)

- Шапка: чекбокс «Режим выделения» → панель инструментов-иконок в духе Claude Design: **Выделить (V) · Двигать (M) · Рука (H)**. Рука = клики идут в саму страницу.
- «Пересобрать дерево» убрать: веб уже синкается сам, Android получает автообновление кадра (пауза во время drag).
- «Сбросить правки» убрать из шапки; сброс по элементу остаётся, новый процесс правок — следующей итерацией.
- Индикаторы «инспектор» / «сервер» показывать только при проблеме.
- Правую панель убрать целиком.
- **Новый процесс правки.** Выделил слой → справа от элемента палитра действий (иконка + текст): Чат с ИИ · Передвинуть · Изменить размер · Скрыть/Показать · Копировать якорь · Сбросить правки · Подробнее (Внутри + свойства). Сверху — крошки родителей.
- «Чат с ИИ» сразу открывает окно: история по этому компоненту + поле ввода.
- После отправки поверх элемента — переливающийся блюр, пока сессия агента работает над ним. Готово → область обновляется, блюр исчезает. Нужен сигнал «готово» от сервера/MCP — уточняется по итогам UI-части.
- Дизайн сделан через design-expert (акцент — пурпурный «ink», белый ореол у контура; кадры прототипа согласуются с пользователем).
- Общая история (ответы без элемента, ошибки агента) — иконка «Входящие» со счётчиком в шапке. В поповере красиво показаны текущие запросы и прогресс по ним: статус, шаги агента, время.
- Кадры дизайна пользователь согласовал 2026-10-06, вёрстка отдана react-ui-expert.
- Сдвиг стрелками в режиме «Двигать» — не нужен.

### Итерация 1 — итог вёрстки (2026-10-06)

Вёрстка по спеке сделана (react-ui-expert), снимки — 57 кадров по матрице. Сервер не даёт точных сигналов статуса — отдельная задача на сервер/MCP:

1. Событие `{ t: 'requestStatus', id, status: 'working'|'done'|'error', error? }` из `handleSubmit` в `src/server/index.ts`. Сейчас ошибка агента приходит общим `{t:'error'}` без id.
2. `reply_in_window` без `requestId` закрывает все забранные запросы разом — нужен `requestId?` в MCP-инструменте, `POST /api/chat` и `ChatMessage`.
3. Нет сигнала «агент закончил» для MCP, если агент не ответил — запрос висит «в работе» до «Не ждать агента».
4. `/api/requests/consume` помечает прочитанными все запросы, а не только выданные.
5. В `ready` нет модели устройства (`deviceModel`) — чип показывает только serial.

## Шаг 2 — найденные баги

- **Встроенный агент молча висит при ошибке авторизации.** Agent SDK получает `401 authentication_failed` и ретраит 10 раз (~4–5 мин) событиями `system/api_retry`; `extract()` в `src/server/agent.ts` их игнорирует, окно всё это время показывает «Агент правит» без причины. Нужно: показывать ретраи и ошибку авторизации сразу с подсказкой (ключ / логин), не ждать 10 попыток на 401. Найдено 2026-10-06.
- **Ошибка агента выглядит как обычный ответ.** `extract()` проверяет `result`-строку раньше `is_error`, поэтому текст ошибки уходит в чат как ответ агента, а запрос помечается выполненным.
- **Техдолг: окно различает ошибки сервера по началу текста** (`Device:`, `Nothing to send…`, `Live edit:` в `src/ui/i18n.ts`). Смена формулировки в `src/server/i18n.ts` молча сломает классификацию. Нужно: код ошибки в протоколе (`{t:'error', code, message}`), текст — только для показа.
- `useServer.ts`: под StrictMode поздний `onclose` выброшенного сокета ставил `online:false` при живом соединении — окно показывало «Сервер не отвечает». **Исправлено** в итерации 1.

- Порты `5174`/`5175` захардкожены в `src/shared/ports.ts`. Если порт занят чужим процессом (другой dev-сервер), инструмент не стартует; переопределить порт нельзя. Найдено 2026-10-06 при запуске окна. **Исправлено** в ветке `worktree-ui-ux-polish`: `LD_UI_PORT` / `LD_SERVER_PORT`, адреса окна сервер подставляет в `/inspector.js` при отдаче.
